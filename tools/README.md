# Скрипты синхронизации базы МИС360 и Git

| Скрипт | Направление |
|---|---|
| `update_mis.bat` / `.ps1` (лежит у Дмитрия локально) | Git -> база: pull, бэкап cf, загрузка из файлов, обновление БД |
| `export_mis.bat` / `.ps1` | база -> Git: выгрузка в файлы, ветка `export/дата_время`, коммит, push, ссылка на PR |

## export_mis: как запускать

1. Положите `export_mis.ps1` и `export_mis.bat` в одну папку (можно прямо `tools\` в клоне).
2. Проверьте настройки в шапке `export_mis.ps1` (`$Repo`, `$V8`, `$IBPath`, `$User`, `$Work`, `$MaxChangedFiles`). `$Work` должна совпадать с папкой из `update_mis.ps1`.
3. Один раз задайте пароль в переменной окружения (новое окно консоли увидит её):
   `setx MIS_1C_PASS "пароль"`. Без переменной скрипт спросит пароль.
4. В Конфигураторе сохраните конфигурацию (Ctrl+S; обновлять БД не обязательно). Конфигуратор можно не закрывать.
5. Запустите `export_mis.bat`. Скрипт спросит описание изменений (оно станет заголовком коммита) и откроет страницу создания PR.

Для планировщика: `export_mis.bat /nopause` (без вопросов; при превышении порога или неизвестном базовом коммите выгрузка отменяется).

## Как это работает

- Клон должен быть чистым; выполняется `git pull --ff-only` в `main`.
- Ветка выгрузки создаётся **от коммита, который загружен в базу**: он берётся из `$Work\db_commit.txt` (пишет export) или из имени последнего `$Work\cf\MIS_<дата>_<коммит>.cf` (пишет update_mis). Поэтому в PR попадают только правки из Конфигуратора, а чужие коммиты из `main` выгрузка не «откатывает».
- Выгрузка идёт в промежуточную папку `$Work\dump` (`/DumpConfigToFiles -update`, первая выгрузка полная и долгая), затем зеркалируется в клон через `robocopy /MIR` (папки `.git`, `tools`, `.github`, файлы `.gitignore`, `ConfigDumpInfo.xml` не трогаются). Так в клоне удаляются файлы объектов, удалённых в базе, а `.git` не может пострадать от полной выгрузки.
- Выводится сводка по затронутым объектам. Если изменённых файлов больше `$MaxChangedFiles`, скрипт спрашивает подтверждение; при отказе клон откатывается, ветка удаляется.
- Файлы под `.gitignore` (например `*.bin` макетов) добавляются принудительно, так как нужны для загрузки конфигурации.
- После push клон возвращается на `main`. После слияния PR запустите `update_mis.bat`, чтобы база получила `main` целиком.

Сливайте PR выгрузки обычным merge (не squash), если до слияния делаете следующую выгрузку: она будет основана на предыдущей.
